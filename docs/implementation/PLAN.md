## Delegation and integration protocol (recorded decision)

- Each implementation worker runs in an isolated staged copy under `.staging/worker-*`
  (robocopy copy excluding .git/build outputs; verified file-for-file equal to the canonical
  tree before dispatch). Workers never write the canonical tree.
- The parent integrates accepted changes file-by-file into the canonical tree, then rebuilds
  and re-runs the full suite before accepting the integration.
- Frozen interfaces are the only contract: policy.hpp, workspace.hpp, context.hpp, tasks.hpp,
  council.hpp, evidence.hpp, validation.hpp, orchestrator.hpp, controller.hpp. Workers report
  interface-change requests instead of editing headers.
- Worker staging directories and build outputs are gitignored (`.staging/`); nothing is
  committed or pushed by workers or the parent.

## Known deviations / decisions recorded

- JSON Schema: the pboettch validator remains a *candidate* per the specification. This build implements a scoped, in-repo contract validator (draft-07 subset) that rejects unsupported vocabulary, with a documented dialect. Recorded as an explicit implementation decision; the candidate remains replaceable behind the same interface.
- MCB-1 canonical profile is defined in contracts/CANONICAL.md (key ordering by UTF-8 bytes; floats rejected in hashed payloads) rather than RFC 8785, which the specification permits when JCS numeric/Unicode rules cannot be met.
- WinUI/Windows App SDK payload: unpackaged, self-contained (specification's proposed layout), subject to the local packaging prototype in M12.
- Kilo Code launch profile: VERIFIED on 2026-10-10 against the installed CLI's own help output (bounded, non-mutating). The installed Kilo Code CLI is OpenCode-compatible: `run [message..] --format json`, non-interactive by default. Launch vector: `run --format json {prompt}`. Flags that select model/provider/reasoning, auto-approve, share or serve are never passed. (Superseded the earlier fail-closed unverified state; the adapter still probe-gates every session.)
- Agent session gating: sessions require (a) a successful bounded probe (READY) and (b) a verified launch vector. This is the fail-closed reading of the specification's containment requirement: no operation proceeds on unverified launch behavior.
- Service-owned schema (delegated services): services create their own tables lazily through the storage owner (CREATE TABLE IF NOT EXISTS via Store::Exec) instead of editing the parent-owned migration registry; parent consolidates into versioned migrations during integration.
